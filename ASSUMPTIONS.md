# Assumptions and decisions

1. **Amounts are integer minor units** (e.g. paise). The assignment examples (100, 50, 30) work unchanged;
   `amount: 5000` means 50.00 if the client treats the unit as paise. Decimals are rejected (400) to avoid rounding ambiguity.
2. **Single currency**; no currency field is stored.
3. **IDs are UUIDs** generated by the database. A malformed ID is `400`; a well-formed ID that does not exist is `404`.
4. **Account `name`** is trimmed, 1-100 characters. Names need not be unique.
5. **Unknown request fields are rejected** (`400`), notably `balance` on account creation, because "the client should not be allowed to set the initial balance".
6. **`description` is required** (1-500 chars, trimmed), because the assignment lists it as a transaction field. **`reference_id`** is required, trimmed, 1-100 chars; `" a "` and `"a"` are the same reference.
7. **Limits:** max 100,000,000,000 minor units per transaction; account balance capped at 2^53-1 so it is always exactly representable. A credit beyond that returns 422 `BALANCE_LIMIT_EXCEEDED`.
8. **Duplicate reference** returns `409 DUPLICATE_TRANSACTION` with the original transaction in `error.details.existing_transaction`. The assignment asks for a response "indicating the transaction already exists"; 409 was chosen over an idempotent 200 so retries are explicit. No balance change and no new row happen either way. A repeated reference with a different payload is treated identically.
9. **Insufficient balance** returns `422 INSUFFICIENT_BALANCE`. Debiting exactly the full balance is allowed.
10. **History defaults:** `page=1`, `limit=20`, `limit<=100`, `page<=1,000,000`. A page past the end returns `200` with an empty `data` array and correct totals. An account with no transactions returns `total_pages: 0`.
11. **Latest-first** ordering is `created_at DESC`, with an internal monotonic sequence as tie-breaker. `created_at` is assigned with `clock_timestamp()` while the account lock is held.
12. **Immutability:** there are no update/delete routes; `PUT`/`PATCH`/`DELETE` on transaction paths return `405 TRANSACTIONS_IMMUTABLE`, and a database trigger blocks UPDATE/DELETE on the table. Accounts cannot be deleted through the API.
13. **`balance_after`** is stored on each transaction (extra field, useful for auditing and reconciliation).
14. **No authentication**; not required by the assignment.
15. **Money transfer (bonus)** is deliberately deferred until the mandatory scope has been run and verified against a real database.
16. **Tests** are integration tests against a real PostgreSQL database (`TEST_DATABASE_URL`), because the guarantees under test (locks, constraints, triggers) cannot be faked by a mock.
